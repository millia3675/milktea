# 밀크티

친구들과 쓰는 비공개 교환일기. 승인된 화면설계를 바탕으로 HTML/CSS/JavaScript와 Supabase 연결 코드를 구현했습니다.

## 현재 상태

- 달력, 개인 일기장, 월/태그 모아보기, 일기 작성/수정/삭제.
- 읽기를 중심으로 정리한 홈: 넓은 PC 화면에서는 한 줄의 일기와 오른쪽 작은 달력, 좁은 화면에서는 ‘월별로 보기’로 펼치는 달력을 제공합니다.
- 카드의 작성자 다음에 제목과 본문을 먼저 표시하고, 태그·생활 기록은 본문 뒤에 모았습니다. 일기 제목과 댓글·날짜의 글자 크기 및 대비를 정리했습니다.
- 본문 중간 사진, 블록 순서 변경, 텍스트/사진 댓글과 반응.
- 일기 글 블록의 첫 줄을 한 글자만큼 기본 들여쓰기. 작성·수정·읽기 화면에 동일하게 적용하며 원문은 그대로 저장합니다.
- 댓글 닉네임 왼쪽에 작성자의 프로필 사진 표시. 사진이 없으면 기존 기본 아바타를 표시합니다.
- 홈 달력 날짜 아래 왼쪽 파란 막대는 친구 일기, 오른쪽 분홍 막대는 내 일기입니다. 게시된 일기가 있는 쪽에만 표시하며 임시저장은 제외합니다.
- 나와 친구의 연참 Weekly/Monthly, 생활 기록 항목, 자동 임시저장. 게시한 일기 날짜로 계산하며 같은 날 여러 편은 하루, 임시저장은 제외합니다. 표시 주기는 보는 사람의 설정을 따릅니다.
- 오늘의 음악: YouTube·YouTube Music 링크와 곡 제목·가수명을 일기에 저장·수정·삭제. 넓은 PC 화면에는 작은 영상과 음악 조작 위젯, 모바일에는 곡 정보와 원본 플레이어만 표시하며 자동 재생하지 않습니다.
- 종이 바탕에 미세한 래스터 노이즈와 부드러운 그림자. 글·사진·스티커의 기존 레이어와 사용자 배경은 유지합니다.
- 프로필 사진 자르기, 100~400% 확대·축소와 가로·세로 위치 조절, 닉네임, 개인 색상. 미리보기와 저장에 같은 자르기 좌표를 사용합니다.
- 기본 무료 폰트 4종(프리텐다드·수트·고운돋움·마루 부리), 뚜씨티콘 스티커 37종, 배경 8종.
- 프로필·반응·연참·일기·댓글의 이모지는 Noto Color Emoji로 표시합니다. 한글·영문·일반 숫자는 선택한 본문 폰트를 유지하며, 업로드한 사용자 폰트에도 적용됩니다.
- 폰트가 맨 위인 꾸미기 라이브러리: 밀크티 기본 / 내 자료 / 다함께 쓰는 자료.
- 스티커·배경·폰트를 여러 파일씩 등록하고, 선택한 자료를 초대된 친구와 공유. 파일별 진행·실패 안내 및 실패한 파일만 재시도.
- 모바일 스티커: 한 손가락으로 이동, 두 손가락으로 확대·축소·회전. 모바일의 크기/각도 슬라이더는 숨깁니다. PC의 슬라이더와 키보드 이동은 유지합니다.
- PC 스티커: 스티커 위에서 마우스 휠로 회전, Shift + 휠로 미세 회전. 선택한 스티커의 네 모서리를 끌면 반대 모서리를 기준으로 비율을 유지하며 크기를 조절합니다. 글 쓰기 모드와 스티커 밖에서는 일반 스크롤이 동작합니다.
- 글과 사진은 항상 스티커보다 앞에 표시.
- 스티커를 붙인 일기는 종이의 폭과 배치를 함께 저장합니다. 작은 화면에서는 글·사진·스티커가 한 장으로 비례 축소되며, 본문을 늘려도 기존 스티커의 종이 좌표는 유지합니다. 종이가 작게 보일 때는 브라우저 확대를 이용할 수 있습니다. 예전 일기는 수정 화면에서 배치를 확인하고 저장하면 고정 방식이 적용됩니다.
- 모바일 메뉴, 사진 확대, 키보드 스티커 이동, 데이터 접근 RLS.

[밀크티 열기](https://millia3675.github.io/milktea/). Supabase 프로젝트 `pnxcakedawwafosqdsqb`에 데이터베이스와 비공개 파일 저장소를 연결했습니다. 초대 메일의 링크에서 12자 이상의 비밀번호를 정하고 승인된 계정으로 로그인합니다. 공개 회원가입은 비활성화했습니다.

별도의 체험 공간은 이 브라우저의 IndexedDB에만 저장하므로 기기마다 별개이며 친구와 공유되지 않습니다. 체험 데이터는 실제 모임에 자동으로 복사되지 않습니다.

## 실행과 빌드

Node.js 24 LTS 환경을 사용합니다.

```sh
npm ci
npm run dev
```

개발 주소는 `http://127.0.0.1:5173/`입니다. 실제 계정으로 로그인하면 연결된 Supabase 데이터를 사용합니다. 별도 체험은 첫 화면의 ‘체험 일기장 열기’를 선택하거나 `?demo=1`로 접속합니다.

```sh
npm test
npm run build
npm run preview
```

`dist/`가 배포 결과입니다. ES Modules와 브라우저 저장 기능을 사용하므로 HTML 파일을 더블클릭하는 방식 대신 HTTP 서버나 GitHub Pages로 열어주세요. 로컬 개발 도구는 127.0.0.1에만 바인딩합니다.

## Supabase 연결

현재 프로젝트에는 아래 초기화와 인증 설정을 적용했습니다. 데이터베이스 마이그레이션 5개와 비공개 버킷 5개가 준비되어 있습니다. 다음 절차는 다른 프로젝트에 설치하거나 친구를 추가할 때 참고합니다.

1. 새 프로젝트를 만들고 `supabase/migrations/`의 SQL 5개를 파일명 순서대로 SQL Editor에서 postgres 권한으로 각각 한 번 실행합니다. 이미 적용한 파일은 반복하지 않고 남은 파일만 실행합니다. 마지막 `202609160005_asset_insert_read.sql`은 파일 등록 직후 반환되는 행을 소유자가 읽을 수 있도록 권한 검사를 수정합니다. 기존 데이터베이스를 덮어쓰는 스크립트가 아닙니다.
2. Auth 일반 설정에서 신규 회원가입과 anonymous sign-in을 비활성화하되, 이메일 로그인 제공자는 활성화합니다. CLI에서는 `[auth].enable_signup=false`, `[auth.email].enable_signup=true`를 사용합니다.
3. `public/config.js`의 supabaseUrl과 publishableKey를 채웁니다. 또는 `.env.example`을 `.env.local`로 복사해 같은 두 값을 설정합니다.
4. Auth URL Configuration의 Site URL을 `https://millia3675.github.io/milktea/`로 지정합니다. Redirect URLs에 `https://millia3675.github.io/milktea/auth-callback.html`을 추가합니다.
5. Auth Users에서 본인과 친구 계정을 생성/초대합니다. 받은 UUID를 `members`에 추가하면 프로필과 기본 설정이 자동으로 만들어집니다.
6. 체험 모드에서 나간 뒤 실제 이메일·비밀번호로 로그인합니다. 두 실제 계정에서 일기·댓글·사진 공유와 타인 글 수정 거부를 확인합니다.

```js
window.MILKTEA_CONFIG = {
  supabaseUrl: "https://YOUR-PROJECT.supabase.co",
  publishableKey: "sb_publishable_...",
};
```

브라우저에 넣을 수 있는 키는 publishable key 또는 기존 anon key뿐입니다. secret key와 service_role key는 넣지 않습니다. 앱도 해당 종류의 키를 거부하도록 구현했습니다. DB 비밀번호도 앱에 필요하지 않습니다.

```sql
-- Auth에 실제 계정을 만든 뒤, 실제 UUID로 바꿔 운영자 SQL Editor에서 실행합니다.
insert into public.members(id) values ('00000000-0000-4000-8000-000000000001');
update public.profiles set nickname='내 닉네임'
where id='00000000-0000-4000-8000-000000000001';
```

회원 접근을 중지할 때는 members.active=false로 설정합니다. 기존 글을 보존하며 이후 DB/Storage 접근을 차단합니다. 회원 완전 삭제와 파일 정리는 별도 운영 절차입니다.

## 초대 링크와 비밀번호 설정

운영자가 직접 전달하는 링크는 밀크티의 `auth-callback.html`로 연결합니다. 페이지를 열거나 새로고침할 때는 인증 토큰을 사용하지 않습니다. 초대받은 이메일을 확인하고 12자 이상의 비밀번호와 확인 값을 입력한 뒤 ‘비밀번호 저장하고 들어가기’를 눌러야 인증과 저장을 진행합니다.

관리자 환경의 `auth.admin.generateLink`로 새 계정에는 `invite`, 이미 이메일이 확인된 계정의 비밀번호 설정 복구에는 `recovery` 링크를 발급합니다. 반환된 `properties.hashed_token`과 인증 종류, 대상 이메일을 URL fragment의 `token_hash`, `type`, `email`에 담습니다. 브라우저는 제출 시 `verifyOtp`를 호출합니다. 관리자 키는 브라우저나 저장소에 넣지 않습니다. 발급한 개인 링크는 해당 수신자에게만 전달합니다.

기존 Supabase 인증 URL은 접속 즉시 일회용 토큰을 사용할 수 있습니다. 이미 사용됐거나 만료된 링크는 새 링크로 교체해야 합니다. 이미 비밀번호를 저장했다면 일반 로그인으로 들어갑니다. 기존 이메일의 세션 복귀 방식과 앱에서 요청한 비밀번호 재설정도 계속 지원합니다.

현재 초대 관리 화면과 별도 SMTP는 연결하지 않았습니다. 운영자가 발급한 링크를 개별 전달하는 방식으로 친구를 추가합니다. 직접 전달하는 링크의 변경이 Supabase 기본 메일 템플릿까지 변경하는 것은 아닙니다.

공식 참고: [메일 미리보기에 의한 일회용 링크 소비와 확인 버튼 방식](https://supabase.com/docs/guides/auth/auth-email-templates), [토큰 검증 API](https://supabase.com/docs/reference/javascript/auth-verifyotp).

## GitHub Pages

제공한 `.github/workflows/pages.yml`은 main에 push할 때 테스트·빌드한 뒤 Pages에 배포합니다. 저장소의 Settings → Pages → Source를 GitHub Actions로 지정합니다. Vite base를 상대 경로로 설정하여 프로젝트 사이트의 하위 경로를 지원합니다.

`public/config.js` 변경 뒤 push하면 연결 설정도 배포됩니다. 공개할 수 있는 URL과 publishable key만 넣으므로 빌드 결과에 포함됩니다. 로그인 화면과 앱 코드는 공개되어도, 일기와 private 버킷 파일은 승인된 사용자만 읽도록 DB에서 검사합니다.

## 데이터와 권한

실제 서비스는 Supabase Auth·PostgreSQL·private Storage를 사용합니다. SQL의 members 목록에 승인된 계정만 데이터에 접근합니다. 본문·스티커·생활 기록은 일기 문서로 함께 저장하고, 파일 참조는 entry_assets 외래키로 보호합니다. save_entry RPC와 version으로 편집 충돌을 감지합니다.

임시저장·개인 설정·읽음 기록·공유하지 않은 미사용 업로드 파일은 본인만 읽습니다. ‘다함께 사용하기’로 등록한 스티커·배경·폰트는 모든 승인 멤버가 라이브러리에서 보고 자신의 일기에 사용할 수 있습니다. 공유 여부는 등록 시 확정하며, 소유자만 목록에서 숨길 수 있습니다. 숨김은 기존 일기와 기본 설정의 참조를 유지합니다. 게시 글·댓글·프로필에서 사용하는 파일은 승인된 친구도 인증된 다운로드로 읽습니다. 일기 주인은 타인의 댓글을 삭제할 수 있으나 수정은 할 수 없습니다.

사진은 브라우저에서 재인코딩 후 업로드합니다. 폰트는 확장자·크기·시그니처와 브라우저 로딩을 확인합니다. 입력된 본문은 HTML로 실행하지 않고 텍스트로 표시합니다. 미디어 자체에 대한 별도 서버 바이러스 검사는 포함하지 않습니다.

Storage 업로드와 DB 저장은 하나의 트랜잭션이 아닙니다. 저장 실패 시 업로드된 미사용 파일이 남을 수 있습니다. 라이브러리에서는 ‘숨기기’를 제공하며, 참조 중인 실제 파일을 삭제하지 않습니다. 고아 파일 자동 정리와 파일 바이트 재검증용 서버는 후속 작업입니다.

## 이모지 폰트

Noto Color Emoji를 앱과 함께 제공하므로 기기에 설치된 이모지 폰트 대신 같은 그림을 사용합니다. 기본 본문 폰트 4종 및 사용자 등록 폰트와 함께 적용되며, 이모지 원문이나 기존 일기 데이터는 바꾸지 않습니다. 추가 SQL 적용도 필요 없습니다.

`public/fonts/noto-color-emoji.css`가 글자 범위별 파일을 필요한 만큼 불러옵니다. Google Fonts v40의 COLRv1 파일과 OpenType SVG 대체 파일을 포함했으며, 실행 중 외부 폰트 서비스에 요청하지 않습니다. 출처·파일 크기·SHA-256은 `noto-emoji-sources.json`, SIL OFL 라이선스는 `NotoColorEmoji-LICENSE.txt`에 있습니다.

일반 숫자와 `#`, `*`의 본문 글꼴이 바뀌지 않도록 별도 키캡 폰트 별칭을 사용합니다. 숫자 키캡·국기·피부색·가족 조합은 Edge에서 실제 사용된 폰트까지 확인했습니다. Safari용 대체 파일을 포함했지만 실제 Safari와 모바일 기기에서의 표시는 별도 확인이 필요합니다.

## 뚜씨티콘과 모바일 조작

사용자가 지정한 PNG 37개를 `public/stickers/ttussicon/`에 원본 그대로 포함했습니다. `src/ttussicon-stickers.json`에 원래 파일명·표시명·크기·SHA-256을 기록하며, 원래 이름의 `#`가 URL 조각으로 해석되지 않도록 파일 URL은 번호를 사용합니다. 작은 이모지 12종은 기본 목록·간편 버튼·내 자료 선택 목록에서 제거했습니다. 예전 일기에 이미 사용한 파일 참조는 보존합니다.

꾸미기 → 스티커 → 밀크티 기본에서 뚜씨티콘을 볼 수 있습니다. 편집기에는 따봉·커피·귀엽 바로가기와 전체 자료 선택창이 있습니다. 선택한 원본은 기존 이미지 처리 과정을 통해 업로드용 WebP로 준비하고, 기존 private Storage 및 일기 파일 참조 방식을 사용합니다. 같은 계정의 동일 기본 스티커를 다시 고르면 저장한 파일을 재사용합니다. 추가 SQL 변경은 필요 없습니다.

모바일에서는 ‘스티커 배치’ 모드에서 스티커를 한 손가락으로 끌어 이동합니다. 두 손가락을 벌리거나 모아 크기를 바꾸고, 두 손가락을 돌려 회전합니다. 작은 스티커는 먼저 선택한 뒤 종이 위 주변 공간에서 두 손가락으로 조절할 수도 있습니다. 손가락 하나를 떼면 남은 손가락으로 이동을 이어갑니다. 배치 영역에서만 브라우저의 기본 터치 동작을 제한하며 ‘글 쓰기’로 돌아가면 일반 스크롤을 사용합니다. PC는 기존 슬라이더도 제공합니다.

크기는 0.25~4배, 각도는 -180~180도로 저장합니다. 선택한 스티커의 크기·각도·위치는 기존 문서 형식에 저장되어 새로고침과 재편집 후에도 유지됩니다.

구현 참고: [Pointer Events의 다중 터치 처리](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Pinch_zoom_gestures), [touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/touch-action).

## 스티커 추가 위치

새 스티커는 현재 보이는 본문 구간의 가운데에 생깁니다. 모바일처럼 도구가 본문 아래에 있어 본문이 화면 밖일 때는 가까운 본문 가장자리를 사용하고, 추가한 스티커로 화면을 이동합니다. 자료 선택창의 닫힘과 초점 복귀가 끝난 후 이동하므로, 추가 직후 다시 도구 버튼으로 스크롤되는 일도 방지합니다.

‘붙인 스티커로 이동’ 버튼으로 선택한 스티커를 다시 찾을 수 있습니다. 일기를 다시 열어 선택된 스티커가 없을 때는 마지막으로 붙인 스티커로 이동합니다. 기존 스티커의 저장 좌표를 바꾸지는 않습니다.

## 반응형 스티커 배치

스티커가 있는 새 일기와 수정 저장한 기존 일기는 종이 폭·높이와 블록 크기를 저장하고, 종이 안의 고정 좌표로 스티커를 표시합니다. 화면 폭이 바뀌면 글·사진·스티커를 함께 비례 축소합니다. 글을 추가해 종이가 길어질 때는 이미 붙인 스티커의 위치를 보존합니다. 글·사진은 스티커보다 앞에 있으며 스티커 불투명도는 65%입니다. ‘앞으로/뒤로’는 스티커끼리의 순서만 바꿉니다. 저장 당시 크기 정보가 없는 예전 일기는 읽기만 해서는 변환하지 않고, 수정 저장할 때 현재 배치를 기준으로 고정합니다.

## 오늘의 음악

작성 화면의 ‘오늘의 음악’에 공유 링크를 붙여 넣고 곡 제목과 가수명을 적습니다. 곡 제목이 비어 있으면 YouTube의 공개 oEmbed 정보에서 불러옵니다. 직접 적은 제목은 덮어쓰지 않으며, 조회 실패 시 직접 입력할 수 있습니다. YouTube 채널명은 가수명과 다를 수 있어 가수명 칸에는 자동으로 넣지 않습니다.

- YouTube·YouTube Music의 watch 링크, youtu.be, 모바일, Shorts·Live·embed 링크, 재생목록/앨범 링크를 인식합니다. 공유용 추적 정보는 저장하지 않습니다.
- 읽기 화면에서 곡 제목과 입력한 가수명을 표시합니다. 제목이 없는 예전 일기도 공개 정보를 조회해 표시하되 저장된 문서를 변경하지 않습니다. 가수명이 없는 경우 조회한 채널을 ‘채널’로 구분해 표시합니다. 조회하지 못한 제목은 ‘곡 제목 미등록’으로 표시합니다.
- 원본 플레이어는 처음부터 펼쳐져 있으며 접기·닫기 버튼이 없습니다. 넓은 PC 화면에서는 원형 재생 버튼·진행바와 200×200px 영상을 나란히 표시합니다. 화면 폭 1,024px 이상이며 음악 영역의 폭도 521px 이상인 경우에만 별도 음악 위젯을 표시합니다.
- 모바일과 좁은 창에는 곡 제목·가수명과 원본 플레이어만 표시합니다. 별도 재생 버튼·진행바·위젯 바탕을 숨겨 세로 공간을 줄이고 원본 플레이어에서 조작합니다. 영상은 가로 폭에 맞춘 16:9 비율과 최소 높이 200px를 사용합니다. 화면 크기가 바뀌어도 플레이어를 다시 만들지 않아 재생 상태를 유지합니다.
- 음악이 있는 일기를 열 때 공식 YouTube IFrame API와 영상을 불러옵니다. 자동 재생은 하지 않으며, 위젯 또는 원본 영상의 재생 버튼을 눌러 시작합니다. 제목 조회도 외부 요청이며 가수·제목을 직접 적은 경우에는 조회를 생략합니다.
- 원형 버튼은 실제 재생·일시정지 상태를 반영합니다. 진행바의 일정한 눈금은 실제 재생 위치이며 음원 분석 파형이 아닙니다. 마우스·터치·키보드로 탐색하고, 재생 길이를 모르면 탐색을 비활성화합니다.
- 원본 영상과 기본 컨트롤을 보이는 상태로 유지합니다. 영상을 가리거나 소리만 분리하지 않습니다. iframe은 최소 200×200px, 모바일 인라인 재생, origin 단위 referrer를 사용합니다.
- 다른 음악을 재생하면 먼저 재생 중이던 음악이 멈춥니다. 다른 탭으로 이동하면 일시정지하고, 페이지 이동 시 플레이어와 타이머를 정리합니다. 늦게 도착한 응답이 이동 후 재생을 시작하지 않습니다.
- 불러오기 실패 시 다시 시도와 원본 링크를 제공합니다. 비공개·지역 제한·로그인·퍼가기 제한이 있는 음악은 원본 서비스에서 확인해야 합니다. 채널·검색·클립 페이지는 개별 영상 또는 재생목록 링크로 바꿔 넣어주세요.
- 제목·가수명·링크를 저장 또는 임시저장하고, ‘음악 빼기’ 후 저장하면 함께 제거합니다. `music: {url, title, artist?}` 형식이며 가수명이 없는 이전 일기도 호환됩니다. 가수명 저장을 위해 새 DB 변경 파일 `202609150004_music_artist.sql`을 포함했습니다.
- 음악 영역은 스티커를 배치하는 종이 밖에 있어 스티커 좌표 계산에 포함되지 않습니다. 재생 상태·위치는 일기에 저장하지 않습니다.

공식 참고: [YouTube 플레이어 규격](https://developers.google.com/youtube/player_parameters), [공식 IFrame API](https://developers.google.com/youtube/iframe_api_reference), [영상 표시 정책](https://developers.google.com/youtube/terms/developer-policies), [퍼가기 및 개인정보 보호 강화 모드](https://support.google.com/youtube/answer/171780?hl=en).

## 이미지 압축과 저장

업로드 이미지는 브라우저에서 크기를 줄인 뒤 WebP 품질 0.86으로 변환합니다. 원본과 변환본을 이중 업로드하지 않습니다. 투명 PNG 스티커의 알파 채널도 유지합니다.

| 종류 | 저장 해상도 | 변환 결과 용량 상한 |
| --- | --- | --- |
| 스티커 | 긴 변 최대 1,024px | 2MiB |
| 일기·댓글 사진, 배경 | 긴 변 최대 1,920px | 8MiB |
| 프로필 | 정사각형으로 자른 512×512px | 1MiB |

프로필 외 작은 이미지는 확대하지 않습니다. 결과가 용량 상한을 넘으면 오류로 안내합니다. 파일마다 줄어드는 양은 다르며, 무조건 특정 KB 이하로 만드는 방식은 아닙니다. 원본은 20MiB 이하, JPEG·PNG·WebP를 받습니다. 스티커는 PNG·WebP를 받습니다.

기본 뚜씨티콘 37개는 자료실에 원본 PNG로 보관합니다. 일기에 선택해 등록할 때에는 같은 WebP 변환을 거칩니다. 기본 자료실의 원본 파일을 다시 압축해 덮어쓰지는 않았습니다.

## 구현 범위와 운영 전 확인

- 원격 Supabase에서 두 임시 계정으로 초대 세션의 비밀번호 설정, 일기·사진·댓글·반응 공유, 임시저장 비공개와 타인 수정 차단을 확인했습니다. 수신함의 실제 초대 메일 도착과 본인 계정의 첫 비밀번호 설정은 사용자가 확인해야 합니다.
- 새 글은 페이지 이동·새로고침 때 반영됩니다. 실시간 구독·푸시 알림·새 댓글 알림은 포함하지 않습니다.
- 친구 일기장에서 게시된 일기 기준 연참을 함께 볼 수 있습니다. 임시저장과 개인 표시 설정의 접근 권한은 기존대로 유지합니다.
- 일반 체험 데이터와 실제 계정 데이터는 분리됩니다. 서비스 모드에서는 브라우저 저장을 공용 데이터베이스처럼 쓰지 않습니다.
- 오래된 글의 편집 자동 저장은 하지 않습니다. 새 초안에만 자동 임시저장을 적용하며 게시 글의 수정은 ‘수정 저장’으로 반영합니다.
- 그룹을 여러 개 만들거나 특정 친구에게만 게시하는 기능, 휴지통, 고급 전체 검색은 포함하지 않습니다.
